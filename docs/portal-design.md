# 入口首頁：系統很多時怎麼呈現

初稿日期：2026-10-13；操作邏輯與版面更新：2026-10-15。

登入前後共用身分首頁與各專區的搜尋、分類，不再切換到另一套個人首頁。舊個人首頁的常用、最近使用、身分看板，以及專用 Razor、JS、CSS 已移除。Server 不自動建立假入口，首頁內容由管理者在串接系統管理登記。

## 登入前的身分選擇

以兩個主要入口「學生專區」、「教職員專區」搭配較小的「校友專區」，選擇後先看公開分類與服務清單，不先要求登入。頁面使用直接的專區與服務名稱，移除宣傳標語。教師與職員合併導覽；入口選擇不作為授權依據，也不覆寫資料庫身分。

三個入口的主題依校方資料整理：

| 入口 | 簡化主題 | 校方資料 |
| --- | --- | --- |
| 學生 | 課程與學籍、學習與獎助、校園生活 | [在學學生](https://www.nkust.edu.tw/p/405-1000-45113,c7048.php) |
| 教職員 | 教學與研究、人事與行政、總務與財務 | [職員](https://www.nkust.edu.tw/p/405-1000-45314,c7048.php)、[教師](https://www.nkust.edu.tw/p/404-1000-62954.php) |
| 校友 | 校友服務、證明申請、職涯資訊 | [校友](https://www.nkust.edu.tw/p/405-1000-45727,c7048.php) |

呈現方式參考 [台科大校務資訊入口](https://i.ntust.edu.tw/)，使用高科大既有校徽與本站視覺，不複製其他學校品牌。教師頁在此次查閱時回應逾時，保留使用者提供的校方指南連結；教職員主題依可讀取的職員頁及使用者指定的合併方式整理。

`/` 與 `/portal` 在登入前後皆顯示同一套身分入口；`/portal/student`、`/portal/employee`、`/portal/alumni` 公開提供分類與搜尋。`PublicStudent`、`PublicEmployee`、`PublicAlumni` 控制哪些系統可公開列出，搭配 `RequireLoginToView` 決定名稱是否公開。`PortalAudiences` 沿用身分群組條件，限制私人入口的顯示與開啟。

點選服務後經由 `/portal/{section}/systems/{id}` 重新確認發布及啟用狀態。純連結預設直接轉往外部網站；管理者可勾選 `RequirePortalLogin`，要求先完成本站登入。SSO 服務一律要求中央登入，ReturnUrl 固定為該服務的本站啟動路徑，登入後再讀取最新登記網址並導向。接收系統自行發起 OIDC、票券或 SAML 請求，不在入口端偽造協定參數。已有有效中央登入時沿用 Session；OIDC `prompt=login` 仍要求一次重新驗證，首次登入也不會重複要求帳密。

帳密 POST 成功後先返回本站 `/account/continue`，再由外部腳本開始一般導覽。這可避免 Chromium 將後續跨站 SSO 回呼判定為帳密表單的跨站提交，維持 `form-action 'self'`。續行頁只接受本站 ReturnUrl，沒有 JavaScript 時提供一般連結；它不產生或延長新的登入。

公開目錄列出的外部網站並不代表已接入本 Server。尤其校友服務系統使用其原有帳號規則，本站不新增校友帳號或推定校友資格。登入頁共用全站 Header；依使用者要求移除「← 返回服務選單」連結。

目前內容區使用淡灰背景、圓角和輕量陰影。首頁三個入口分別採學生靛藍、教職員深青綠、校友紫色背景；統一使用淺色文字與白底按鈕，維持同等操作層級。首頁維持最大 1120px 的大入口卡片，學生與教職員整張可點，右下固定顯示操作文字；校友維持較小的橫向入口。各入口使用本機 SVG 輔助辨識。全站 Header 使用校徽與中英文校名合成的單一橫式官方圖片，保留原始比例；「校務資訊入口」作為次要標示。圖片本機檔案為 `wwwroot/nkust-logo-horizontal.png`，來源為[高科大官方圖片](https://www.nkust.edu.tw/var/file/0/1000/img/513/182513897.png)，2026-10-15 取自[校首頁](https://www.nkust.edu.tw/index.php)。

Header 上方提供「回校首頁」、「忘記密碼」及前台中英切換。下方導覽列採淡藍底、深色文字，保留學生、教職員、校友與常見問題；目前頁面以深一階底色與底線辨識。760px 以下使用可收合選單，支援鍵盤、Escape 及 `aria-expanded`；無 JavaScript 時仍能看到完整導覽。沒有「專區選擇」導覽項或「← 返回專區選擇」連結；點 Logo 返回 `/portal`。

首頁下方的登入提示與「校方服務指南」區塊已移除。四個學生／教師／職員／校友官方指南集中於不需登入的 `/faq`，並提供登入、SSO、密碼重設、身分權限與校友帳號說明。問題採原生 `details` 展開，支援鍵盤及無 JavaScript 瀏覽。

公開服務選單在寬於 1000px 時，左側固定放搜尋與分類，右側分組顯示每列兩張的服務卡；1000px 以下，搜尋與分類移到上方；640px 以下服務卡改為單欄。分類可以換行，無需橫向捲動；每張卡片下方保留「登入使用」或「開啟服務」。

服務卡片預設只呈現名稱、登入狀態與操作按鈕。`RegisteredSystems.Description` 或 `DescriptionEn` 非空時，滑鼠移入或鍵盤聚焦顯示詳述，也可用獨立的「功能說明」按鈕點擊展開（支援觸控，不會開啟服務）。說明可停留供滑鼠移入閱讀，按 Escape、點擊區塊外或切換搜尋／分類可關閉；詳述仍參與搜尋。沒有詳述時不顯示說明按鈕；停用 JavaScript 時以文字作為備援。

### 中英介面與英文內容

前台支援繁體中文與 English，範圍包含身分首頁、公開目錄、常見問題、登入／續行／登出及權限提示；管理後台維持中文。`portal-language.js` 集中維護介面譯文，使用 `textContent` 與屬性更新，不引入外部翻譯服務或 HTML 插入。切換同步更新 `html.lang`、標題、讀屏名稱及動態狀態，不重新載入、不清除搜尋或表單值，也不變更 ReturnUrl、驗證與授權。

語言只存於瀏覽器 `localStorage` 的 `nkust.portal.language`；同來源分頁同步更新，儲存被封鎖時仍可在當頁切換。停用 JavaScript 時提供完整中文頁與導覽，不顯示無作用的語言按鈕。

英文內容優先使用管理者填寫的 `PortalCategories.NameEn`、`RegisteredSystems.DisplayNameEn` 與 `DescriptionEn`。未填名稱時依既有標準詞彙提供譯名，自訂名稱及未翻譯詳述保留中文並標示 `lang="zh-Hant"`；不冒充機器翻譯結果。中英文名稱與詳述皆可搜尋，語言不影響排序、發布或身分限制。首次啟動以 `AddColumns` 為舊資料表增加空白英文欄位，不覆寫既有中文內容；未提供英文的內容須由管理者逐步補齊。

排序數字越小越前面，建議以 10、20、30 預留插入空間；同排序時分類依 `Key`、服務依 `ClientId` 排列。公開目錄每次讀取資料庫，保存後重新整理即可套用，不需改 Razor 或重啟。中文詳述沿用既有欄位，英文詳述使用同表的 `DescriptionEn`，不另建重複資料表。分類與服務排序是跨身分共用的設定，目前沒有每個身分獨立排序或拖曳排序。

登入頁改為最大 520px 的單欄白色卡片，移除大型插圖與重複校徽。卡片頂部以淡色身分標籤辨識學生、教職員或校友，搭配藍、青綠、紫色主按鈕；文字名稱仍是主要辨識依據。帳密欄位採 16px 字級與至少 54px 高度，手機縮減邊距，英文與錯誤訊息可換行。資料來源、驗證、密碼顯示切換與 ReturnUrl 流程不變。登入頁已移除「其他服務」及其連結；「帳號使用說明與服務聯絡窗口」移入卡片，位於登入按鈕下方，預設收合。

公開首頁、服務選單與登入使用 `clean-layout.css` 的共用顏色變數，版面分別由 `header.css`、`gateway.css`、`directory.css`、`login.css`、`faq.css` 管理；所有樣式與圖形均在本機，維持原有 CSP。身分專區將登入者身分、姓名與學號／員編放在專區標題右側；其他頁面顯示於頁首右側，管理入口位於專區導覽列。

無障礙功能包含跳至主要內容、鍵盤焦點、語意標題、分類選取狀態、搜尋結果播報、新分頁提示、登入失敗訊息焦點、高對比與減少動畫偏好。`tests/gateway.py` 已實測 320、390、768、1024、1440px 五種視窗寬度、可見文字對比、鍵盤操作、展開說明區塊與登入導向，且 CSP 違規與 JavaScript 錯誤為零。這些檢查不取代 NVDA／VoiceOver 人工驗收，也不代表已取得無障礙認證。

2026-10-15 重新查閱上述校方學生、職員及校友指南，`PortalDefaultDataInitializer` 一次匯入 35 個實際公開服務連結，協定皆為 `link`，不產生帳號、密鑰或假串接。既有識別碼與網址完全吻合、仍顯示的純連結只補公開專區欄位；其他既有系統保持原狀。版本標記確保重啟不補回被刪除或取消發布的服務。之後統一由既有系統與分類管理介面維護。

## 目前的操作流程

1. 開啟 `/portal`，或開啟 `/`：顯示學生、教職員與校友入口；整張卡片可點。
2. 進入任一專區：不需登入，可以搜尋服務與切換分類；選擇專區不會變更使用者身分或授權。
3. 點選服務：以 `target="_blank" rel="noopener noreferrer"` 開新分頁，原頁搜尋與分類不變。伺服器依專區重新查詢發布設定及私人入口的身分條件；未發布、已隱藏或已停用的 SSO 入口回傳 404。純連結不以「啟用 SSO 登入」決定是否顯示。
4. 依下表決定是否要求登入；需登入但未登入時，帶原專區與固定的本站 ReturnUrl 導向 `/account/login`。
5. 登入成功後經 `/account/continue` 返回原服務的本站入口，再次確認發布設定後，導向目前登記的 `EntryUrl`。
6. 再開其他需要登入的服務：有效中央 Session 可沿用；Session 到期、撤銷或協定要求重新驗證時仍需登入。不能以「瀏覽器沒關」保證永遠不必登入。
7. 登出本站：返回 `/portal`；不代表所有外部系統同步登出。

| 服務設定 | 尚未登入本站 | 已有有效本站登入 |
| --- | --- | --- |
| `Protocol = link`，`RequirePortalLogin = false` | 顯示「開啟服務」，另開分頁前往外部網站 | 同樣直接開啟 |
| `Protocol = link`，`RequirePortalLogin = true` | 顯示「登入使用」，在新分頁先登入本站 | 顯示「開啟服務」，直接前往外部網站 |
| OIDC／票券／SAML 串接 | 顯示「登入使用」，先登入本站，再前往接收系統啟動登入協定 | 顯示「開啟服務」，前往接收系統並沿用有效中央登入；明確要求重新驗證時除外 |

`RequirePortalLogin` 只控制經由本站入口開啟服務的流程，並非外部網站的存取控制；使用者直接開啟外部網址時仍由該網站管理。接收系統須完成協定整合才能得到真正的 SSO 效果。

## 公開名稱與私人入口

「需先登入本站」與「登入後才顯示」是不同設定：

| 設定 | 未登入 | 登入後 |
| --- | --- | --- |
| 指定專區、不勾登入後才顯示 | 名稱與說明公開；需要登入的服務顯示「登入使用」 | 沿用有效 Session，點擊直接前往服務 |
| 指定專區、勾登入後才顯示 | 名稱、詳述與搜尋資料都不輸出 | 僅符合 `PortalAudiences` 身分條件者看得到與開啟 |
| 未指定任何專區的既有私人入口 | 不公開任何資訊 | 沿用舊身分條件，在各專區列出；可指定專區並勾登入後才顯示以縮小放置位置 |
| 取消「在首頁顯示入口」 | 不顯示 | 不顯示 |

匿名者與身分不符者直接要求私人入口網址時回傳 404；每次開啟重新檢查最新身分、發布與啟用設定。個人條件使用同一筆有效身分完整比對，不跨身分拼湊條件；入口選擇本身不授予資格。公開項目的身分授權與功能權限仍由接收系統管理。以上限制只保護本站入口，不能取代外部系統的存取控制。

尚未登入者可從導覽列最右側的「登入」登入並回到原專區。所有服務卡片皆由使用者點擊時原生開啟新分頁；登入與 ReturnUrl 接續在該分頁進行，不於登入完成後才呼叫 `window.open`。同瀏覽器分頁共用有效的中央登入 Cookie，`noopener` 防止接收網站操控原頁；無 JavaScript 仍可開啟連結。原頁保留當時畫面，需要更新私人項目時重新整理即可。

### 登入者資訊的位置與更新

「常見問題」同一條導覽列最右側統一放登入／登出：未登入時顯示「登入」，登入後只顯示「登出」。手機版保留在選單開關右側，不必展開導覽才能操作。登入者資訊採兩行排版，上方為身分標籤與姓名，下方為學號／員編；學生標示「學號」，教師、職員及教職員標示「員編」，其他身分標示「帳號」。缺少姓名時隱藏姓名欄。

身分專區標題右側顯示登入者資訊；手機版換至標題下方並維持靠右。其他頁面保留頁首右側的登入者資訊。身分來自實際登入帳號，不由目前選擇的專區推定；來源僅提供教職員時顯示「教職員」。使用本機已保存的姓名與帳號，不額外查詢校務資料，不顯示班級、學年期、學籍與查詢提示。教職員另顯示所屬單位（來源 `emp_untid`），同樣讀登入時保存的快照，不即時查校務來源；學生的系所來自班級，不走這個欄位，離職等非在職身分也不顯示。單位對照不唯一或來源沒給名稱時整行隱藏，不以代碼代替名稱。未登入者不顯示個人資訊；跨分頁登出會一併清除姓名及帳號，中英切換僅翻譯身分與欄位標籤。

切回分頁或從瀏覽器返回快取時，由 `header.js` 查詢本站 `/account/current-user`，更新帳號、身分與登出防偽 Token，不重載清單或清除搜尋。端點只回傳 `signedIn`、`userName`、`identityLabel`、管理入口顯示資格及登出防偽資訊，禁止快取，並檢查帳號可用狀態。帳號以文字節點更新，不存入 localStorage。不背景輪詢以避免持續延長閒置 Session。停用 JavaScript 時仍由伺服器輸出登入資訊。

其他分頁登入後，原專區的私人服務清單需重新整理載入；新分頁中的登入與接續服務流程不變。`tests/user_header.py` 驗證跨分頁登入／登出、防偽 Token 更新、停用帳號、匿名資訊限制、中英顯示及手機版。

舊分頁或開發時的局部更新可能缺少新版班級元素，`header.js` 對選填元素先檢查存在，再更新或清除；核心元素不完整則保留原生操作。相容測試涵蓋匿名、登入、伺服器錯誤與網路中斷，避免清除狀態時再次拋出例外。

具 SsoAdministrator 管理角色的帳號，在登入者資訊旁顯示「選單管理」，連至 `/admin/systems`，可進入新增選單功能；一般使用者不顯示。伺服器每次查詢實際角色並回傳 canManageSystems，切回分頁時同步更新，避免原本匿名頁面的頁尾沒有隨登入更新而找不到入口。新增與維護操作仍由既有 ManageSessions 授權政策檢查；本次未更動正式帳號或授予角色。
