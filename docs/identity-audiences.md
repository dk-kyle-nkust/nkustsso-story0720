# 身分分類與群組規則

## 職責與資料來源

來源資料庫提供帳號、身分與分類資料。本專案只查詢來源，管理各系統的開放規則及 SSO 管理權限；不對來源執行新增、修改、刪除、建表或同步寫回。

登入者的人員狀態沿用 `s90_auth_usr.sts_id` 對照 `s90_auth_status.sts_name`，例如 `10` 顯示「已離職人員」。
登入時將來源代碼與名稱保存至自有帳號的 `SourceStatusCode`／`SourceStatusName`，重新登入時更新，
頁面讀取快照而不額外查詢校務來源。名稱缺漏或對照不唯一時沿用既有身分大類顯示，不猜測狀態。
這是狀態顯示，並不改變登入允許規則、`IdentityType` 分類、管理角色或外部串接欄位。
教職員另在登入時以 `s10_employee.emp_untid` 對照 `dbo.s90_unit.unt_name_full`，保存至帳號的
`UnitCode`／`UnitName` 供頁首顯示所屬單位。此關聯尚未以實際資料核對，所以代碼空白或
`unt_id` 對照不唯一（可能跨校區重複）時名稱留空，不取第一筆、不以代碼代替名稱，也不影響
姓名取得與登入結果。走所屬單位而非工作單位 `emp_wuntid`；學生的系所仍由班級關聯提供。
已離職人員（校務代碼 `10`）仍以帳號對應 `s10_employee.emp_id` 讀取 `emp_name`，
顯示原始狀態、姓名與帳號；不將離職身分改成在職教職員。人事資料缺漏或不唯一時不任取姓名。

本地 SQLite 保存系統登記、首頁開放規則、管理者角色、Session、稽核紀錄及必要的登入顯示快照。這些資料不等同來源的人事或學籍資料，不會反向更新來源。

`/admin/identity-catalog` 是唯讀查詢畫面，需 `SsoAdministrator` 角色。不提供新增種類、選項、編輯或啟用／停用；原相關 GET／POST 路由已移除。名稱與分類代碼如需調整，交由來源管理單位處理。來源沒有提供的選項不以本地示範值補上。

| 種類 | 遠端來源 | 使用欄位 | 現況 |
| --- | --- | --- | --- |
| 身分類別 | `dbo.s90_auth_status` | `sts_id`、`sts_name` | 已接入分類頁及開放規則 |
| 學生狀況 | `dbo.s90_srckind` | `srckind_id`（varchar 1）、`srckind_name`（varchar 60） | 例如復學生、轉學生；使用獨立種類 `student_kind`，學生紀錄關聯待確認 |
| 部別 | `dbo.s90_division` | `dvs_id`、`dvs_name` | 已讀取選項，學生部別關聯待確認 |
| 系所／單位 | `dbo.s90_unit` | `unt_id`、`unt_name_full`、`unt_sort_seq` | 已讀取選項，學生依班級關聯；教職員以 `emp_untid` 關聯，僅供顯示，尚待實際資料核對 |
| 校區 | `dbo.s90_cmparea` | `cmp_area`（int）、`cmp_name_full`（varchar 45）、`cmp_name_abr`（varchar 24） | 全名優先，空白時用簡稱，再空白用代碼；人員校區關聯待確認 |
| 學籍、學制、任職／任用、年級 | 待確認各對照表與人員關聯 | 不自行推測 | 分類頁標示待串接，規則不提供新增選取 |

透過既有 `ConnectionStrings:LoginAuth` 連線，`CampusAuthentication:Enabled=true` 時共用遠端來源。分類頁與開放規則由 `CampusIdentityCatalog` 讀取同一份來源，不另建分類同步工作。原有本地排序若與來源種類／代碼吻合則保留；否則使用來源排序或代碼順序。本頁不提供排序編輯。外部連線帳號應由 DBA 授予所需 SELECT 權限。

來源相同代碼與相同名稱可合併，代碼相同但名稱不同時不任取一筆，回報讀取失敗，須確認是否需要校區等複合鍵。來源故障時分類頁顯示錯誤，系統規則禁止儲存；指定群組不因缺資料變成不限。「全部身分」仍代表所有已登入使用者。

## 開放規則

在「串接系統管理」編輯系統，於「首頁入口開放身分」選擇全部身分或指定群體。

1. 新增學生、教職員或其他身分群組。
2. 選擇身分類別；選項名稱與代碼直接來自 MSSQL。大類依 `StatusIdentityTypes` 映射，未知代碼歸其他身分，不推測其業務意義。
3. 使用「繼續細分」加入已串接的條件。少量選項使用勾選，多於 8 項提供搜尋多選；系所／單位使用可搜尋、展開的分層勾選清單。
4. 確認摘要後儲存；規則、版本與稽核紀錄只寫入本專案資料庫。

群組之間 OR，同組條件 AND，同一條件多個選項 OR；每組須由同一筆身分完整滿足，不混用不同身分的資料。缺少已指定屬性時不符合條件。最多 16 組，每組最多 16 個條件，每個條件最多 100 個值。空群組集合或空的指定選項不可自動變成全部。沒有個人白名單、黑名單或個別例外。

系所／單位依四碼代碼呈現兩層：例如 `IC00` 是 `IC01`、`IC02` 的上層，僅在同前兩碼的 `XX00` 確實存在時建立顯示關係；末兩碼須為數字。其他格式或找不到上層者獨立顯示。分類清單預設只顯示第一層，可逐一展開下層；維持來源階層順序，不提供欄位排序。搜尋查找所有層級，保留明確的上層名稱與代碼，清除搜尋後回到第一層。分頁與筆數依目前顯示的列計算。

規則編輯器提供同樣的分層勾選清單，限制清單高度以減少整頁捲動。搜尋下層時保留上層作為脈絡；收合、搜尋或清除搜尋都不取消既有選取。選取上層只保存該代碼，下層仍需各自選取，未改變既有規則的精確代碼比對，也不會自動納入未來新單位。選取數量及下方完整摘要可核對目前規則。

這些規則目前控制首頁入口顯示；直接呼叫 OIDC、SAML、Web API 單一登入的流程，以及下游功能授權，仍由各自的驗證與授權流程處理，不能只把隱藏入口當成權限防線。

## 登入者身分對應

校務來源帳號在首頁比對時，按 `SourceAccountId` 讀取 `s90_auth_usr.sts_id`，以原始代碼比對來源分類，例如 `02`。不載入全校人員或密碼。學生單位依以下 LINQ LEFT JOIN 讀取：

```text
s90_auth_usr.usr_id → s30_student.std_id
s30_student.cls_id → s90_class.cls_id
s90_class.unt_id → s90_unit.unt_id
```

以帳號在資料庫端篩選；空白關聯不匹配空白代碼。學生或班級／單位關聯不唯一時，不任取一筆加入身分屬性。尚未確認的部別、學籍與任用資訊留空。當學期查無資料不可直接推論為畢業或退學。

`Account.IdentityType` 及對外既有 claim 仍使用 `student`、`employee` 等通用值；本次來源分類的原始代碼用於入口規則，未變更下游欄位契約。既有規則中的通用身分代碼保留相容比對，但不出現在新的來源選項清單，亦不能新增選取。既有未串接或示範條件保留其限制，不會自動移除而放寬範圍。

既有 `AccountIdentityService.ReplaceAsync` 多重身分快照介面僅供內部相容與測試，沒有個人身分編輯頁或對外寫入 API。校務來源目前直接讀取帳號的單一 `sts_id`，完整學生兼職員等多重身分仍須串接實際人員關聯。非校務的既有快照仍按來源、版本、生效期限檢查，不因無有效身分回退成不限。

## MSSQL 帳密驗證

`dbo.s90_auth_usr.usr_id` 為登入帳號，`usr_mdpwd` 使用既有天方格式。`MssqlCampusAccountSource` 與 `TienFangPasswordVerifier` 在記憶體驗證，不保存或回寫來源密碼。天方格式為舊式可逆格式，並非雜湊；空值、損壞格式與非 ASCII 字元不猜測修復。

`sts_id` 不限制 SSO 登入，已移除 `AllowedStatusIds`。`StatusIdentityTypes` 僅負責分類，未知或空白代碼轉成 `other`，仍須正確帳密；分類不自動授予管理角色。來源帳號重複則拒絕；顯示資料缺漏或不唯一時以帳號顯示。學生讀 `s30_student`、`s90_class`、`s90_unit`，教職員讀 `s10_employee`。完整來源欄位模型位於 `Models/External`。

來源驗證成功後才建立本地固定識別與最小顯示快照，不做整份人員同步。同名本地帳號不自動連結；啟用校務登入後，原本地示範帳號不適用。管理角色為本地 `SsoAdministrator`，須明確指派。

密碼失敗計數保存在本地 `CampusLoginAttempts`；連續五次失敗鎖定五分鐘，首次成功前也適用。來源故障回報暫不可用，不計密碼錯誤，也不回退本地密碼。多 worker／多主機需另做共享原子節流。中央 Session 會重新檢查來源帳號及分類；分類改變需重新登入更新快照，不表示新分類禁止登入。來源密碼變更與下游 Cookie 尚無即時撤銷通知。

連線強制加密，憑證信任依 `TrustServerCertificate` 設定；預設驗證憑證，明確設定 `True` 時略過驗證，正式部署應使用可信任憑證及 `False`。查詢逾時由 `CommandTimeoutSeconds` 控制。參見 [README](../README.md#mssql-校務登入設定)。

## 待確認與驗證

`D:/Code/ForgotPassword` 僅作模型與程式參考，其來源使用 Sybase ASE，不能直接假設所有 MSSQL 結構相同。已確認帳號對身分、學生及教職員的查詢；仍需核對 `s30_sturec`、`s90_yms`、`s90_srcstatus` 的目標結構與學籍判斷，班級學制對部別、教職員部別／單位，以及校區複合鍵。教師、公務人員等細分不得由員編或名稱推定。

保留原本地分類與規則資料，不因改為唯讀查詢而刪除歷史設定。以下測試使用合成資料及隔離服務：

```powershell
dotnet build NkustSSO.slnx --no-restore
dotnet run --project tests/NkustSso.StorageChecks --no-build
python tests/catalog.py
python tests/identities.py
```

檢查包含來源唯讀限制、分類更新、不明／衝突來源、原始身分代碼比對、舊規則相容、移除的 GET／POST 路由，以及桌機／手機版面與 CSP。來源分類頁截圖位於 `.local/catalog-ui-checks/`。實際 MSSQL 已通過分類唯讀讀取；不以測試新增或修改任何來源資料。
