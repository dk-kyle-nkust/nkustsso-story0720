傳輸格式

項目SOAP 1.1SOAP 1.2
Content-Typetext/xml; charset=utf-8application/soap+xml; charset=utf-8; action="http://tempuri.org/方法名"
Envelope namespacehttp://schemas.xmlsoap.org/soap/envelope/http://www.w3.org/2003/05/soap-envelope
ActionSOAPAction: "http://tempuri.org/方法名"放在 Content-Type action；若提供須與 Body 一致

必備授權與回傳規則

  • 管理者登記 SOAP、實際來源 IP、允許方法及允許回傳欄位。SOAP 同一來源 IP 只能對應一筆啟用登記；共用 NAT 無法僅靠舊參數分辨應用。
  • Certify2 驗使用者帳密；Certify1 驗舊校務票據；其餘方法另需要登記的呼叫系統帳密。三者不可混用。
  • 陣列以固定位置解析。DataSet 使用 XSD＋DiffGram，建議用 WSDL 產生代理或 DataSet 支援工具，不能當普通 JSON。
  • 個資欄位須逐方法授權；未授權通常保留欄位但清空值。pwd 固定空字串，不提供密碼或密碼摘要。
  • 失敗 DataSet 可能只有 message 欄，不可先直接讀取 std_id 等成功欄。
失敗層級處理
HTTP 403來源或方法未授權。
HTTP 503SOAP 服務未啟用。
HTTP 500／SOAP Fault請求格式、尚未支援的方法或來源不可用；不能視為成功。
HTTP 413／415／429大小、Content-Type 或頻率不符；上限 16 KiB、每 IP 每分鐘 60 次。
HTTP 200 業務失敗依各方法的 boolean、NoPass、400／500／501 判定，不以 HTTP 200 判成功。
不支援帶帳密的 GET、舊表單 POST 繫結或額外 SOAP Header。from_Clientip 不是授權依據，來源以中央實際連線 IP 判定。

聯調時必測

  • 核對舊程式使用 SOAP 1.1 或 1.2、參數大小寫、ArrayOfAnyType 型別及 DataSet 解析方式。
  • 逐方法測試正常結果、錯誤呼叫帳密、未授權 IP、取消欄位授權、來源中斷。
  • 交通類測試查無、重複或缺漏資料；文件方法測試多列結果；Certify1 測試逾時與重放。
  • 未授權欄位空白及 pwd 空白時，接收端不得誤判為完整資料或繼續使用舊快取權限。
舊 SOAP 的校務票據與 Web API 的 ticket 是不同來源、格式與驗證端點。不得把 /ticket/authorize 取得的 ticket 送入 KuasSSO_Certify1。
